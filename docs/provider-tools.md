# Provider tools

`/tyan` and `/tyans` retain their category buttons and chat NSFW preference. [Nekos.best](https://docs.nekos.best/getting-started/api-reference.html) supplies exact supported SFW image/reaction categories, including available artist and source credit. [Purrbot](https://docs.purrbot.site/api) supplies SFW `lick` and NSFW `neko`/`blowjob` through its current `api.purrbot.site/v2` API. GIFs are sent as native animations. The existing `neuro` category keeps its separate generator.

SFW `shinobu`, `megumin`, `bully`, `awoo`, `glomp`, `kill`, `cringe` and NSFW `waifu`/`trap` currently have no validated replacement. Their buttons explain that the category is unavailable; they never return a different random category. The retired Waifu.pics hosts are not used. Each metadata lookup has an eight-second deadline including capacity waits, a 16 KiB body limit and at most one retry for transient GET failures. DNS/TLS failures and ordinary HTTP rejections are not retried. A short per-provider cooldown prevents repeated failed lookups and honors bounded rate-limit delays. Only a definite Telegram rejection of a media URL can select another image; uncertain Telegram sends are never replayed.

`/pdf`, `/topdf`, `/to_pdf` and automatic document previews use PDF24's [conversion tool](https://tools.pdf24.org/en/convert-to-pdf). The adapter selects an available worker from the site's current manifest, uploads once, polls the job and downloads the finished PDF within the same session. Worker hosts are restricted to PDF24; redirects, oversized bodies, unsuccessful jobs and non-PDF downloads are rejected. One conversion has a 180-second deadline, 20 MiB input and 50 MiB output limits. The public website protocol can change independently of the bot.

Plain text is escaped into UTF-8 HTML before conversion so Cyrillic survives the service's plain-text font limitation. UTF-8, BOM-marked UTF-16 and Windows-1251 are supported. Text never becomes active markup. Office documents and images preserve their original format for conversion. Documents go to PDF24; its [privacy policy](https://tools.pdf24.org/en/privacy-policy) governs remote processing and deletion. Returned files are uploaded to Telegram directly rather than exposing provider job URLs.

`/ddg`, `/wiki`, `/вики` and `/duckduckgo` retain DuckDuckGo instant answers and redirects where available. Empty or unavailable instant answers fall back to the [Wikipedia Action API](https://www.mediawiki.org/wiki/API:Action_API), with Russian selected for Cyrillic queries and English otherwise. Replies retain the source link. If both services fail, the encoded search link remains available. The requests use an identifying User-Agent, bounded response bodies and a shared 25-second deadline.

`/bg` runs U²-NetP locally and returns a transparent PNG. Photos stay on the bot's server. Input admission uses the shared media executor; the worker accepts at most 20 MiB/16 MP/8192 pixels per side and reduces the output's longest side to 2048 pixels. Inference uses one CPU thread, a 45-second process deadline and a 1 GiB Linux address-space limit. Existing transparency is preserved. Fine hair, shadows and foreground/background ambiguity can still produce imperfect edges.

The Docker build explicitly downloads the fixed, checksum-verified model into the installed package. For local development, run `uv run python -m msu_hub_bot.media.background_model fetch` after installing dependencies. Inference never downloads models, accepts model URLs or falls back to cloud processing. The model source, checksum and license are recorded in [background_model.py](../src/msu_hub_bot/media/background_model.py) and [third-party notices](../THIRD_PARTY_NOTICES.md). The offline Docker smoke check verifies a real foreground/background mask.

`/i` and `/imgur` use Imgur's official upload API and the configured `HUB_IMGUR_AUTHORIZATION` header (`Client-ID …` or an authorized bearer token). A failed upload is reported without returning provider bodies. Polling has a finite deadline; a configured key or reachable website alone does not establish that uploads are permitted or working. Validate upload permissions with a synthetic image before treating a new hosting configuration as operational.

## Link previews

[Link orchestration](../src/msu_hub_bot/telegram/links/service.py) owns automatic URL selection, preferences and delivery. X, VK, YouTube, Instagram and TikTok keep their provider-specific extraction; [shared rich output](../src/msu_hub_bot/telegram/links/rich.py) owns text limits, custom-emoji fallback and ordered sends. The source message remains intact and replies stay in its forum topic. Known site routes never fall through to another extractor after a failure.

YouTube, Instagram and TikTok use `auto_video_links`, respect commands, active conversations and explicit preview suppression, and skip unavailable content quietly. Native headers use their custom platform logo, plain author name, linked username when known and a source arrow. Other yt-dlp sites retain their ordinary 📺/🎞 formatting and existing extraction behavior; `/song` keeps its media adapter.

YouTube previews require a successfully downloaded video; thumbnail-only and text-only cards are not published. Shorts attempt an uploaded H.264/AAC video with its soundtrack when a finite duration is known and no greater than three minutes. Ordinary watch links stay quiet. Source timestamps are preserved rather than silently clipping the upload. Public oEmbed can fill missing title/author metadata after a successful video download. Unavailable formats, provider restrictions and failed downloads leave the original link without an extra bot reply.

Instagram public posts and Reels preserve complete captions and ordered photo/video carousels. The typed adapter retains source media kinds and container counts from yt-dlp; missing video formats never turn a failed video into a photo. TikTok handles public video/photo posts and bounded `vm`/`vt`/`t` short-link resolution. Photo posts become ordered slideshows with their title and full text. Homepage/login redirects are not successful extraction. Incomplete albums are skipped rather than presented as complete. Profiles, feeds, stories, private content and live-stream capture are outside automatic post expansion.

[Download workers](../src/msu_hub_bot/providers/link_download.py) run in killable subprocess groups under the shared executor. Each post has an absolute deadline; requests, redirects, response bytes, decoded photos, video duration and output files are bounded. Photos are normalized to JPEG, videos are probed for real geometry and compatible codecs, and available smaller renditions are preferred to failed oversized uploads. Media limits are 9 MiB per photo, 49 MiB per video and 100 MiB per post. Temporary media and signed URLs are not persisted; children do not retain application secrets or browser/account configuration. Failure is observable through fixed provider/outcome telemetry without exporting source content.

VK post links and `/vk_post` use the API version pinned in [the adapter](../src/msu_hub_bot/providers/vk/api.py), with a small [Pydantic model subset](../src/msu_hub_bot/providers/vk/models.py) based on the [official schema](https://github.com/VKCOM/vk-api-schema). Its custom logo is added only to parsed user links, never by the default repost publisher. Unknown fields are ignored; malformed posts are skipped, and unsupported attachments retain a link to the original. Privileged-token access is never sufficient for publication: the outer wall and copied source walls must report themselves open. Deleted, archived, paid, friends-only and private-key posts are excluded; access keys on public attachments do not make a post private. Privacy metadata is checked afresh for each operation rather than cached across requests.

Wall reads are capped at 100 posts and 30 seconds; individual requests have a 15-second deadline, 4 MiB response limit and at most three attempts for VK rate-limit errors. Error bodies and echoed request parameters are discarded. Rendering escapes labels and URLs once, chooses a Telegram-compatible photo size and sends at most ten media items. Long posts retain their full text in reply-linked messages: chunks preserve anchors and respect Telegram's parsed-text, raw HTML and link-count limits. The preview appears once on the last chunk, followed by media once; complete short posts can use album captions. Automatic repost publication remains disabled; the [community interface](community-tools.md) manages paused targets and read-only previews.

Public posts, copies, photos, videos and clips retain their attachment handling, including video playlists and attached communities. Copied bodies, original links and authorship are shown for up to ten distinct entries across two levels; deeper or larger histories retain the outer source link. Public location metadata supports coordinate strings, coordinate objects and named places, with validated map links; an explicit hidden-map flag keeps only the place label. Scheduling, suggestions, ad-only records and unknown post formats remain excluded. Unsupported attachment formats, including `photos_list`, link back to VK instead of silently disappearing.

## Native X posts

Public `x.com` and `twitter.com` status links, plus ordinary `fixupx.com`, `fxtwitter.com`, `twittpr.com` and `xfixup.com` aliases (including `www`), use [FxEmbed's v2 API](https://docs.fxembed.com/) without credentials. The [adapter](../src/msu_hub_bot/providers/fxembed.py) preserves full text, ordered media, quoted authorship, polls, community notes and available article content. Private/deleted sources are not expanded. Quotes that cannot be loaded remain visibly unavailable; an article excerpt is labelled as an excerpt. Poll results are a snapshot, with voting left in X.

Concurrent reads of the same post share one in-flight provider request and receive independent models. Completed results are discarded, so a later request checks the source again. Cancelling one caller leaves other readers running; the last caller's cancellation closes the shared request.

The [renderer](../src/msu_hub_bot/telegram/links/x.py) sends [Telegram Rich Messages](https://core.telegram.org/bots/api#sendrichmessage): author → full text → gallery → quote. The header starts with a custom logo emoji, followed by the unlinked display name, linked X username and a `↗` link to the post. The header and body share a paragraph with an internal blank line, since clients trim paragraph edges. Rich blocks carry explicit links so X usernames do not become Telegram mentions. A media facet disappears from the text only when its matching attachment is displayed. Text is split into reply-linked messages only when rich-message limits require it.

Uploads use validated X CDN URLs, bounded time/bytes and temporary files. An oversized original photo gets one attempt at the CDN's `large` rendition; partially downloaded originals still consume the shared byte budget. Videos carry the selected variant's dimensions when available, otherwise the source dimensions, preserving aspect ratio within Telegram's limits. Unavailable media retains an original link. A definite custom-emoji rejection retries once with the ordinary fallback emoji; definite rich-format/media rejection falls back to complete plain text. Uncertain Telegram writes are never retried.

`auto_x_previews` is independent of `auto_video_links` in chat settings and the Mini App. An absent X preference inherits the stored video preference. Automatic expansion respects commands, active conversations and explicit preview suppression, retains the trigger message, and replies in its forum topic. At most two distinct post links are considered per message; aliases of the same post and media selector are deduplicated. FxEmbed links explicitly requesting another layout, a download or a translation are left alone. X and FxEmbed domains never fall through to automatic yt-dlp extraction, including media selectors and unsupported routes.

Reply-based tools read rich text and nested media through [shared extraction](../src/msu_hub_bot/telegram/rich_input.py). Rich authorship, source links and quoted commands do not trigger automatic handlers. [Media diagnostics](observability.md) summarize preparation counts, recovered photos, fixed omission reasons and bucketed download sizes. Private diagnostics may include canonical public source URLs under the link-source contract; signed media URLs, post bodies and response payloads are excluded.
