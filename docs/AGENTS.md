# Documentation

- Keep tracked documentation small and durable: explain supported behavior, architecture, configuration and operations. Isolate unfinished plans, review queues and session progress in ignored workspace storage.
- Do not include temporary state, session dates/counts or short-lived work narratives in maintained docs/comments. Preserve evidence privately rather than rewriting an audit to look like a completed fix.
- Keep public documents free of credentials, private repository references, operational addresses, chat identifiers and raw review notes.
- Separate observed behavior, user decisions, recommendations and unverified assumptions. Cite primary documentation and dated compatibility evidence; Reviewed does not mean shipped.
- Use `tvly` for web searches after checking its help; use Context7 for library/API documentation. Never send private review notes or credentials as search queries.
- Keep maintained links valid and remove superseded documentation rather than accumulating parallel versions.
